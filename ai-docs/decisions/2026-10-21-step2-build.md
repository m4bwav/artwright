# Step 2 build rulings (2026-10-21)

Small design rulings made while building, each flagged in one line in the session's final message. Forks for the
owner stay in the synthesis; these are within the brief.

## B1. One shared evergreen unit at the root, 60 days

The four skills share one plugin-level unit in pointer mode, as historywright does. The interval is 60 days (the
synthesis), not the moderate default of 30. Three volatile claims carry their own recheck: `law.md` every 45 days,
the judge's model profiles every 60, the market gold answers every 180.

## B2. Only PICO-8 ships built in; other palettes are fetched on request

Lospec's API page invites per-slug fetches on a user's request, but its terms forbid copying "any portion of the
Service", and no licence was found for Sweetie 16, Endesga 32 or DawnBringer 16/32. PICO-8 is CC0 (Lexaloffle's
FAQ). So `aw.py` bundles PICO-8 only and caches any other slug in `ARTWRIGHT_HOME/palettes/` when the user names it.
Source: R-20261021-24.

## B3. Knowledge files sit under each skill's `references/`

Hub: movements, theory, traditions, evidence, craft, ceramics, market, law, cli. Judge: rubric, verdict-contract,
vocabulary, ai-look, models/. Pixel: pixel-art, sprites-tiles. Curate: store. The script lives in the hub
(`skills/artwright/scripts/aw.py`) and the other skills call it by relative path, as historywright's skills call
`hw.py`.

## B4. The work folder is `<folder>/artwright/`

`compare`, `rank` and `verdict` share one folder per batch (default `./artwright`): `pairs.jsonl`, `matches.jsonl`,
`pairs/*.png` and `verdict.json`. Paths inside `verdict.json` are relative to the folder that holds `artwright/`,
so the same file works inside a polywright asset folder. The private store stays in `ARTWRIGHT_HOME`.

## B5. Pair images are one two-up picture per order

`compare prepare` writes one image per order with the two candidates side by side, labelled 1 and 2 by a built-in
5x7 bitmap font (no font files, no ffmpeg drawtext), 768 px cells. Two Reads per pair instead of four. Labels and
grey padding are neutral; file names never appear.

## B6. Stats follow the verified definitions

Colourfulness takes the nearest Hasler–Süsstrunk Table 2 anchor (they are anchor points, not band edges); RMS
contrast is the SD of L* as in the Aesthetics Toolbox; balance is reported as `imbalance_pct` (0 is centred), with a
note that it is one centre-of-mass offset, not the toolbox's eight-axis Balance. Sources: R-20261021-23, -25.

## B7. Grid detection: a lattice must beat chance

A clean upscale shows 98% or more of colour changes on one lattice; that scale wins. Otherwise the peak-spacing
mode (the unfake edge-profile idea) is the estimate, but only when the changes gather on it at 1.6 times chance or
more; else the scale is 1. This keeps native-resolution art from being read as upscaled.

## B8. vocabulary.md and ai-look.md are flagged as a whole

Their rows are descriptive craft usage, not facts with one source each, so each file carries one verification line
(`verified: no` as a whole; cited lines are the exception). Row-level flags stay for movements, theory, traditions,
evidence, craft, ceramics, market, law and the pixel files.

## B9. Evals: 14 cheap cases and 18 paid cases, fixtures generated

Cheap tier (8 triggers, 3 decoys, 3 actions) uses `tool_used` graders only. Paid tier (outcomes and guards) uses an
`llm` grader plus regex graders and runs in Step 3. Fixtures come from `evals/fixtures/make_fixtures.py`; `--net`
adds the Cleveland CC0 images by accession number with the hashes pinned in `tests/test_aw.py`. Nothing in
`evals/fixtures/out/` is committed.

## B10. The release workflow waits for the owner

The first commit carries the tests workflow only. A release workflow (tag check, zip, GitHub release) goes in its
own pull request, assigned to the owner with `needs-review`, because the owner's rules keep release and publish
workflow changes for review.
